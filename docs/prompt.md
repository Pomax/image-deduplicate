You're going to create a cross-platform executable with a GUI that takes a folder of images (with a way to say whether or not to scan subfolders) and then builds a sqlite index file that links each image (keyed on relative path in the folder) to one or more scale and rotation invariant identifiers that can be used for image comparison (e.g. SIFT fingerprint, quantized histogram, etc). The application should then be able to find all suspected duplicates in the index, and preset all suspected duplicates as a list of sets, with a way to select which image to keep in each set, and a way to clean up after making the selection. There should be a way to automatically mark "the most likely candidate to keep" so that the user only needs to correct selections that are wrong. Use human criteria for this (e.g. "looks the best", "highest resolution from among a set of identical images", etc). You are free to use whichever language is the most appropriate for this kind of work, it can be either compiled or a scripting language, but it has to be fast. Speed is the absolute most important aspect, as it will be run on folders with tens of thousands of images. Also note that if the application is run on a folder multiple times, it needs to first update the index (throwing away any paths that  no longer exist, and indexing previously unseen images). The index should also store a file's timestamp, so that we can tell whether or not an image may have changed and needs reindexing, or is still the same image.
